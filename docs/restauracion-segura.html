Probar y restaurar un respaldo

Comprobar sin reemplazar datos

Configuración → Protección y mantenimiento → Probar respaldo. Selecciona una copia .sqlite3 y pulsa Comprobar copia. Solo Administrador puede hacerlo. Para archivos mayores de 32 MB o si Aula no abre, utiliza Inicio de Windows → Aula Colegio → Probar respaldo.

Se revisa una copia temporal y se elimina al terminar. No escribe archivos en el USB/carpeta del respaldo. Muestra integridad, referencias, versión, alumnos, pagos, último recibo y saldo registrado. No restaura, migra ni genera mensualidades. Las copias actuales siguen sin cifrar.

Restaurar con revisión

  1. Cierra Aula completamente con Colegio → Salir y cerrar Aula. X puede ocultar la ventana y dejarlo funcionando.
  2. Inicio de Windows → Restaurar respaldo → seleccionar copia.
  3. Revisa base actual y respaldo: alumnos, pagos válidos/anulados, último recibo y sus fechas, cobrado USD y cambios que se perderían o revertirían. No se comparan solo fechas: se utiliza identidad y contenido.
  4. Sin diferencias que perder, escribe RESTAURAR. Con diferencias, RESTAURAR CON PÉRDIDA DE DATOS.
  5. Se preservan copia previa verificada, originales, candidata e informes PDF/CSV. Si falla la preparación o cambió la revisión, no reemplaza.
  6. Al terminar, guarda las rutas mostradas. Abre Aula y revisa saldos y recibos. Puede solicitar confirmar reloj y tasa.

La restauración reemplaza toda la base, incluidos usuarios y configuración. No fusiona PC ni deshace un solo movimiento. Los informes identifican pagos/egresos por correlativo, fecha, persona, importe/moneda, método, referencia y estado; no exportan cuentas bancarias ni contraseñas. Se registran en bitácora y restauraciones.json.

Numeración

Con base actual legible, conserva los máximos de seis correlativos de ambas bases. El siguiente recibo no reutiliza un R- de un pago sustituido. Los saltos se explican por la restauración o borrados previos.

Base dañada

Muestra No se pudo comparar, nunca cero movimientos. Conserva sus archivos y exige RESTAURAR SIN PODER COMPARAR. Si no puede leer los últimos números, pide revisar los seis correlativos. Si no los conoces, cancela y solicita ayuda: una copia antigua no permite deducir un número desconocido de una base dañada.

Interrupción o registro pendiente ilegible

Una operación confirmada se completa al siguiente inicio antes de abrir la base o generar mensualidades. La copia anterior siempre se conserva. Si .restore-pending.json está truncado/ilegible o falta una copia verificable, Aula se detiene con Recuperación pendiente.

Conserva toda la carpeta y solicita ayuda técnica. No borres el registro pendiente, WAL, SHM ni los respaldos. Los cortes automatizados usan datos temporales; no cortes la luz ni mates el programa con datos reales. Mantén un UPS y copias externas.

Prueba manual con datos ficticios

  1. Usa otra PC/cuenta Windows de prueba sin información real. Crea alumno/cargo ficticios y cobra $10; anota R-.
  2. Descarga copia A; registra otro pago de $5 y anota R-.
  3. Probar respaldo sobre A muestra solo el primer pago y no modifica el historial actual.
  4. Cierra Aula, restaura A con confirmación reforzada y revisa segundo R- en PDF/CSV.
  5. Abre y registra un tercer pago: su R- debe superar al segundo.
  6. Restaurar antes-restauracion recupera la base previa completa, pero también requiere revisión y puede dejar fuera el tercer pago.

Aula - Pruebas sirve para experimentar, pero no descarga respaldos y elimina su base al cerrar. La prueba completa de restauración necesita la instalación/cuenta ficticia indicada.
